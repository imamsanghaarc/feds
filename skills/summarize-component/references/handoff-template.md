# Handoff Template

Use these sections in order. Drop a section only when it would be empty of facts.

## 1. Component Context
- Name and purpose
- Framework, and where it lives in the repo
- Lifecycle status (draft / in review / approved / published)

## 2. Issue
- The concrete symptom, in one or two sentences
- Steps to reproduce, if known
- User-visible impact

## 3. Resolution or Implementation Steps Taken
- What was actually changed or attempted
- Links to saved tasks or components from the workspace
- Performance and accessibility notes already recorded

## 4. Current Status
- One of: not started, in progress, blocked, ready for review
- Blockers, with owners where known
- Explicitly mark anything that is assumed rather than verified

## 5. Recommended Next Action
- A single concrete next step
- Name the reviewer or skill if a human decision is required

## Rules

- Bullets over paragraphs.
- Never state a test passed unless the result is in the supplied context.
- Keep inference visibly separate from recorded fact.
- Core Web Vitals targets when performance is discussed: LCP < 2.5s,
  FID/INP < 100ms, CLS < 0.1.
